# Forge Health Bases View

Forge adds a **Forge health** layout to Obsidian Bases. It shows cached Forge
health for only the files already present in the active Base result set.

## Requirements

- Obsidian 1.10 or newer
- The Bases core plugin enabled
- Forge enabled

Forge 3 requires Obsidian 1.10.0 or newer because the Bases API is now a
first-class Forge surface.

If you enable Bases after Forge is already running, turn Forge off and back on
once so Obsidian can register the layout.

## Add the view

1. Open or create a Base.
2. Open the current view menu in the Bases toolbar.
3. Change the layout to **Forge health**.
4. Adjust the Base filters to define which files Forge health should display.

The Forge view never broadens the Base query. A file appears only when the Base
itself supplies that file.

## Health states

| State | Meaning |
|---|---|
| Errors | Latest cached lint or Shape results contain an error for the file |
| Warnings | Latest cached lint or Shape results contain a warning for the file |
| Needs review | Latest cached lint identified a review item for the file |
| Clean | The file was included in a cached scan and has no findings |
| Not scanned | No current cached scan records the file |

Each row includes the note link, lint counts, Shape issue count, review reason,
and latest relevant scan time. Normal click, modifier-click, and hover preview
behavior follow Obsidian's file-link conventions.

## View options

Open the view options menu to configure:

- **Minimum severity** — all findings, review and higher, warnings and errors,
  or errors only.
- **Include clean notes** — show files scanned without findings.
- **Include not-scanned notes** — show Base entries absent from the latest cache.
- **Group by health status** — organize rows into health-state sections.

## Cached results

Base filter and property updates only rematch the current Base entries against
Forge's cached health index. They never start a vault scan, read every note, or
write health fields to frontmatter.

The header shows whether results are recent, old, or have never been generated.
Use **Open Vault Health** for full issue details.

Use **Refresh Forge health** when you intentionally want to run the existing
Vault Health refresh workflow. That command may update Forge reports, cache
files, exports, and any maintenance behavior you explicitly enabled in Forge
settings. It does not add health fields to your notes.

## Large Bases

Forge builds one path-keyed index from the cache, then performs constant-time
lookups for the Base entries. It does not reread note content while rendering.
Rows also use deferred off-screen rendering. Filtering the Base before
displaying the view remains the best option for very large vaults or narrow
mobile panes.
